## 1. 全体構成

### 1.1 ボトムナビゲーション（4タブ）

| タブ         | 画面キー    | 内容                                                                   |
| ------------ | ----------- | ---------------------------------------------------------------------- |
| トレーニング | `home`      | ホーム。標高カード＋4タイル（トレーニング/ミッション/動画/MYフレーズ） |
| 記録         | `records`   | 学習履歴・連続達成・カレンダー・ランキング・スピーキング履歴           |
| トーク       | `talk_list` | AI友達・コーチ・お知らせ・グループチャット・サポート                   |
| マイページ   | `mypage`    | プロフィール・目標設定・プラン                                         |

### 1.2 起動〜初回導線

`splash` → `auth`（サインアップ/ログイン）→ `ob1`〜`ob5`（オンボーディング5問）→ `obperm`（マイク/スピーカー許可）→ `obdone` → `home`

- **認証**：メールアドレス＋パスワード（8文字以上）。サインアップ時は利用規約の確認（WebView）と同意が必須。トークン（JWT）は端末に保存し、期限切れ・失効（401）で破棄する。メールアドレスは大文字小文字を区別しない
- **セッション復元**：起動時に保存済みトークンがあればプロフィールを取得し、`onboarding_step` から途中再開する（オンボーディング完了済みなら `home`）
- **オンボーディング**：各ステップの「次へ」でプロフィールと現在地をサーバーに保存する。自由記述が短い場合は、追記を促すヒントを表示する
- **`obperm`**：マイクはOSの許可を実際に取得する（未許可では次へ進めない）
- **`obdone`**：プロフィール保存とオンボーディング完了の通信が両方成功した場合のみ `home` へ進む（失敗時はその場で再試行）。完了時に、プロフィールからAIが専用のMYフレーズ教材を作り始める（6.4）

## 3. トレーニングHub（`input_hub`）

トップに「今日の発話時間／学習時間」ウィジェット（それぞれ、1日の目標に対する達成率のリング＋分数。ミッションHubと共通）。以下3メニューを同列表示：

### 3.1 初級文法トレーニング（`unitmap` → `unitdrill`）

- ユニットマップ形式（UNIT表示、進行中/完了/未着手のステータス）
- ユニット詳細（`unitdrill`）：日別タブ、例文一覧、「答えを見る」トグル
- **現状は固定データのプレースホルダー**（進捗・解答は実データではない）。ハブ上のバッジ（「UNIT 10・DAY 2/5」）も固定表示

### 3.2 シチュエーション別課題（`situational`）

AI（OpenAI）が生成する教材。2形式に大別：

**① ダイアログ形式**（複数人でのやり取りが本質的なシーン）

- 対象シーン：社内ミーティング／同僚との会話／社外でのやりとり
- `situational_dialogue`：プロフィール（職業・職位・職業詳細）に合わせてAIが生成する会話文。生成に失敗した場合は固定の会話文にフォールバックする。再生成は画面内で1回まで（端末内の制限。サーバー側では強制しない）
  - 各セリフに「再生」「スラッシュリーディング切替（セリフ単位）」「MYフレーズ登録」の3アイコンを吹き出し下部に配置
  - 全体を1本の音声として扱う共通プレイヤー（TTS。play/pause、±5秒/±10秒シーク、再生速度0.75〜1.5x）
  - 横スワイプでEN/JP切り替え（ページドット付き）
- `dialogue_roleplay`：全セリフを1画面に縦並び表示。相手のセリフ＝再生（何度でも可）、自分のセリフ＝録音ボタン。下部に一括「練習を終える」
  - **自分のセリフの録音は見せかけ**（タイマーが動くだけで音声は保存されない。「確認する」は準備中）

**② プレゼン形式**（一人語りが本質的なシーン）

- 対象：プレゼンテーション
- `presentation_material`：プロフィールに合わせてAIが生成する4段落構成の長文原稿。ダイアログと同じ音声プレイヤー／スラッシュリーディング／EN-JPスワイプ仕様
- `presentation_practice`：原稿全文を参照表示しつつ、通しで1回録音 → 提出してAI添削（合否＋コメント）。結果はミッションの履歴には記録しない

- 過去に生成した教材：最大5件をインラインプレビュー、超過分は `situational_history_full` で全件表示（**現状は固定データ**。ハブ上の「本日あと1回生成可」も固定表示）

### 3.3 フリー練習（`freetraining`）

- 音読／英語ピッチ／発音練習／Q&A練習／ロールプレイ／シャドーイングの6メニュー
- 現状はすべて `daily_task`（質問回答タイプ）に遷移する簡易実装（`origin=freetraining`）。AI添削は受けられるが、**Dailyミッションの実績としては記録しない**。将来的にはカテゴリごとに専用コンテンツを持たせる想定

## 4. ミッションHub（`speaking_hub`）

トップに「今日の発話時間／学習時間」ウィジェット（トレーニングHubと同一コンポーネント）。以下3メニューを表示し、各メニューのバッジに現在の実施状況を出す（画面表示のたびに取得）：

| メニュー | バッジ                                                   |
| -------- | -------------------------------------------------------- |
| Daily    | 「今日 n/2 実施」／2種類とも実施済みなら「今日は実施済み」 |
| Weekly   | 「STEP n/6 完了」／今週の発話テスト実施済みなら「今週は実施済み」 |
| Monthly  | 「MYピッチ・残りn日」／今月実施済みなら「今月は実施済み」 |

### 4.1 Dailyミッション（`output` → `daily_task`）

- 2種類から選択：**写真描写ミッション**（写真を見て英語で説明）／**質問回答ミッション**（質問に英語で回答）
- フロー：録音（実マイク・タイマー表示）→ 停止 → 確認する（音声プレイヤーで聞き直し）／録り直す → 提出してAI添削 → **合否＋添削コメント＋文字起こし＋見本の解答例（英文/和訳）を表示**
- AI添削：録音を音声認識（Whisper）で文字起こしし、LLM（gpt-4o-mini）が課題への回答として合否とコメントを返す（`POST /api/grade`）
- **合否の記録はサーバー側**：採点の結果を、サーバーが `daily_mission_results` に日付×種別（photo/question）ごとに1件保存する（同じ日の再提出は最新の結果で上書き）。アプリ側から合否を直接送ることはできない

### 4.2 Weeklyミッション（`weekly_material` → `weekly_step` ×6 → `weekly_practice`）

- 週のミッションは**STEP1〜6の学習 → STEP7の発話テスト**の流れ。STEP1〜6を順番に完了しないと次に進めず、STEP7は6完了後に解放される。進捗はサーバーに保存し、週（月曜始まり・日本時間）が変わると0に戻る

| STEP | 内容                     | 完了条件                                       |
| ---- | ------------------------ | ---------------------------------------------- |
| 1    | 語彙・表現チェック       | 確認して完了                                   |
| 2    | 語彙・表現テスト（4択）  | 正答率80%以上                                  |
| 3    | スラッシュリーディング   | 読んで完了（英文の横スワイプで日本語表示）     |
| 4    | 音読                     | 音声を聞き、読んで完了                         |
| 5    | シャドーイング           | テキストを隠して練習し、完了                   |
| 6    | 反訳トレーニング         | 全段落の答え合わせを表示                       |
| 7    | 発話テスト（`weekly_practice`） | 通し録音 → AI添削 → 合否＋コメント      |

- STEP2の合格判定・STEP6の完了条件は**アプリ側のみで判定**（サーバーは STEP の順序のみ検証）
- 発話テストの結果は、**STEP1〜6を完了している場合のみ**サーバーが `weekly_mission_results` に週ごと1件保存する
- 教材は現状**固定の1本**（WEEK 14）。週替わり生成は未実装

### 4.3 Monthlyミッション（`mission`）

- 月1回のスピーチ課題「MYピッチ」。録音導線＋**スピーチ原稿メモ欄**（自由入力、下書き/コピペ用。端末内のみで保存しない）。見出しの月は現在の月
- AI添削の結果は、サーバーが `monthly_mission_results` に月ごと1件保存する（月1回の制限は未強制）

## 6. MYフレーズ（`phrase` → `phrase_folder` / `phrase_history`）

### 6.1 構成

- 上部の「フレーズ／単語」タブで内容種別を切り替え、種別ごとに以下3種類のフォルダを表示する：

| 種類                 | `source`   | 作られ方                                                             | 生徒による編集 |
| -------------------- | ---------- | -------------------------------------------------------------------- | -------------- |
| カスタマイズ教材     | `curated`  | プロフィール（職業・趣味・性格・経歴など）からAIが生成する           | 不可           |
| 運営提供             | `official` | 管理画面で用意した教材を、生徒のPhase（レベル）に合わせて自動配布    | 不可           |
| マイフォルダ         | `custom`   | 生徒が自由に作成                                                     | 追加・編集・削除・フォルダ名変更が可能 |

- カスタマイズ教材・運営提供の中身は読み取り専用（「覚えた」の切り替えのみ可能）。教材側の追加・変更・削除は、生徒の「覚えた」状態を保ったまま反映される
- 「覚えた履歴を見る」から `phrase_history` へ

### 6.2 フレーズ・単語の登録（共通コンポーネント）

以下から起動する登録シート：

1. ダイアログ画面：セリフごとの登録アイコン（テキストは自動入力・編集不可）
2. プレゼン/Weekly教材の「MYフレーズに登録する」ボタン（テキストは自由入力）
3. 英文の単語長押しの辞書ポップアップ（13.1）
4. フォルダ画面の「このフォルダにフレーズを追加」ボタン（マイフォルダのみ）

登録シート共通仕様：本文（表示 or 入力）＋日本語訳（任意）＋種別（フレーズ/単語）＋マイフォルダ選択（既存チップ or その場で新規作成）→「登録する」。登録・編集・削除に失敗した場合はアラートで知らせる

### 6.3 フォルダ詳細（`phrase_folder`）

- フラッシュカード形式（左右スワイプで前後へ移動）：英文／和訳表示トグル／音声再生／（マイフォルダのみ）編集
- 「覚えた」ボタン：**1日1回まで**カウントされ（同じ日に何度押しても1回。日付はサーバーの日本時間で判定）、**3回覚えると一覧から外れて履歴に移る**。カードの下にカウント（0/3〜）を表示
- 以前あった「クイズ」機能は廃止

### 6.4 AI生成（カスタマイズ教材）

- オンボーディング完了後、および `phrase` 画面を開いたときに、まだ無いフォルダをAIが生成する（フレーズ3カテゴリ・単語2カテゴリ、各8個。学習者のPhaseに合わせた難易度）。生成中は空表示のまま、数秒〜1分ほどで表示される
- 「AIで追加」ボタンで、既存のものを消さずに新しいフレーズ・単語を追加する（続けて押すとクールダウンで断られる。失敗しても連打できない）
- 生成はバックグラウンドで実行され、AI呼び出しは1人あたり毎分30回までに制限される

### 6.5 覚えた履歴（`phrase_history`）

- 3回覚えたフレーズ・単語を、覚えた日ごとにまとめて表示（フレーズ/単語の件数サマリー付き）
- 「復習に戻す」で覚えた回数を0にして復習に戻す（元のフレーズが残っていなければ、同種別のマイフォルダに作り直す）

## 7. 記録（`records`）

### 7.1 学習履歴セクション

- 個人／グループのスコープ切替、日別/週別/月別/全期間の期間タブ
- 棒グラフ（発話時間・その他学習時間の積み上げ）：**タップした棒の詳細を下の集計表に表示**（実績/目標の分数のみ。目標は「当時の目標」を使う）
- グラフ左右に「前後の期間ウィンドウへ移動」ナビ（日別=7日ずつ、週別=6週ずつ）
- 「＋新規登録」から任意の日に学習記録を直接追加可能
- 個人スコープは**サーバーの実データ**。グループスコープは固定のモックデータ

### 7.2 ランキングセクション（学習履歴の直下）

- 個人スコープ時：**全ユーザランキング**（約30名のモックデータ中でTOP10表示。圏外なら自分の順位を「…」区切りで別途表示）
- グループスコープ時：**グループ間ランキング**（自分の所属グループ vs 他グループの合計学習時間で順位付け）
- 期間は学習履歴セクションの期間タブと連動（専用トグルは持たない）
- **他ユーザー・他グループのデータは固定のモック**（`GET /api/ranking`。取得できない場合は端末内の固定値にフォールバック）。実集計は未実装

### 7.3 カレンダーセクション

- 月表示。記録がある日は色付き＋ドット表示、タップで内容確認・編集。**1日に複数件の記録を登録・編集・削除できる**（学習時間は1〜1440分）
- 記録がない日をタップすると新規登録シートが開く（過去日への遡り記録が可能。未来日は選べない）
- **連続達成**：1日の学習目標を達成した日を数え、バナーに連続日数と自己ベストを表示。今日まだ未達成でも、日付が変わるまでは連続を途切れさせない。炎の色は 1日〜=オレンジ／7日〜=赤／14日〜=金／30日〜=虹色
- 達成日は色付きの帯で表示し、連続した日は帯をつなげる
- **お休み**：旅行・体調不良の日を「お休み」にすると、連続達成が途切れず日数にも数えない。**月4回まで**、2日前から先の日に設定でき、過ぎた日のお休みは取り消せない（後出しで連続記録を守るのを防ぐ）。日付の判定はサーバーで検証する

### 7.4 スピーキング履歴セクション

- Daily/Weekly/Monthlyミッションの結果（**サーバーの実データ**）と、フリー練習・シチュエーション別課題などの活動ログ（**固定のモック**）を**1本の履歴に統合**
- 種別フィルタ（全て/Daily/Weekly/Monthly/その他）と合否フィルタ（全て/合格/不合格）を独立して掛け合わせ可能
- 各行に種別ごとの合否バッジ（アイコンのみ、テキストなし）

### 7.5 グループ関連（`group_members` / `member_detail`）

- 「グループのメンバーを見る」からメンバー一覧・個人の週間学習時間・スピーキング履歴を閲覧可能（閲覧専用、コメント等の機能なし）
- **現状は固定のモックデータ**（実グループとは連動していない）

## 8. トーク（`talk_list`）

### 8.1 一覧構成（上から）

1. **aグループ**（グループチャット。**固定のモック**）
2. 広告バナー（管理画面で設定、表示先＝`talk`）
3. **運営からのお知らせ**（公式・一方向配信のみ。管理画面で「公開」した、全生徒宛て または 自分の所属グループ宛てのお知らせを表示）
4. AI友達：Justin / Bob / Sara（英語）、セレン（日本語）※すべて通話ボタンあり
5. 田中コーチ／佐藤チューター（人間、通話不可）。**田中コーチのスレッドは管理画面の生徒詳細と同じチャット**（コーチが送ったメッセージが届き、生徒の送信もコーチに見える）。佐藤チューターは固定のモック
6. カスタマーサポート（人間、通話不可。固定のモック）

### 8.2 機能

- `talk_thread`：1:1チャット。**AI友達はLLM（gpt-4o-mini）が人物設定（persona）に沿って短く返信する**（直近12件の履歴を、1件あたり先頭1000文字までAIに渡す。失敗時は定型の返信にフォールバック）。コーチへのメッセージは1回2000文字までで、超えるとサーバーが受け付けない

## 11. 実装状況（実連携済み／モック）

### 11.1 実バックエンド・AI連携済み

1. **AI添削**（Daily/Weekly/Monthlyミッション・プレゼン練習）：録音の文字起こし（Whisper）＋LLM（gpt-4o-mini）による合否とコメント。ミッションの合否はサーバーが記録する
2. **録音**：実マイク録音（expo-audio）。録音ファイルをサーバーへアップロード（25MBまで）
3. **音声再生**：OpenAI TTS（tts-1）でその都度生成し、サーバーにキャッシュ。声は、プロフィールの音声性別に応じて選ぶ
4. **教材生成**：シチュエーション別ダイアログ・プレゼン原稿・MYフレーズのカスタマイズ教材を、プロフィールを元にLLMで生成
5. **動画**：管理画面で登録したYouTube動画
6. **サーバー同期**：学習記録・目標・お休み・ミッション結果・Weekly進捗・MYフレーズ・チャット・お知らせ・広告バナー・プロフィール・アバター
7. **AI友達のチャット**：LLMが人物設定に沿って返信
8. **管理画面との連携**：生徒詳細・グループ・お知らせ・動画・広告・教材の編集がアプリに反映される

### 11.2 まだモック／未実装

1. **通話機能**：タイマーのみ。実際はWebRTC等のリアルタイム音声通信基盤が必要（実装負荷が高いため後続フェーズ）
2. **ランキング（全ユーザ／グループ間）**：固定のモックデータ。実際は全ユーザー・全グループの集計APIが必要
3. **グループ関連**：グループチャット・グループメンバー・過去の所属グループは固定データ
4. **ユニット（初級文法）**：ユニットマップ・詳細・「答えを見る」は固定データ。ハブのバッジも固定表示
5. **フリー練習**：専用コンテンツなし（すべてDailyの質問回答に遷移）。活動ログ（スピーキング履歴のその他）は固定のモック
6. **Weekly教材**：固定の1本（週替わり生成は未実装）
7. **ロールプレイの録音**：見せかけ（音声は保存されない）
8. **端末内のみで保存されるもの**：動画の視聴済み、Monthlyのスピーチ原稿メモ、ターム目標の履歴
9. **シチュエーション別課題の「本日あと1回」**：表示のみで、サーバーでは制限していない
10. **有料プランの決済**：LP表示のみ

### 11.3 環境変数・運用メモ

- サーバー：`OPENAI_API_KEY`、`ADMIN_JWT_SECRET`・`STUDENT_JWT_SECRET`（`NODE_ENV=production` では未設定だと起動しない）、`ADMIN_EMAIL`・`ADMIN_INITIAL_PASSWORD`（本番では必須。管理者が1人もいないときだけ最初の運営管理者を作り、初回ログイン後に変更を強制する）、`PORT`
- アプリ：`EXPO_PUBLIC_BACKEND_URL`（未設定なら開発用サーバーのURL）。管理画面：`VITE_BACKEND_URL`
- 日付・週・月の判定は**日本時間（JST）基準**（サーバー）。端末から送る「今日」は、サーバー日付から±1日以内の場合のみ採用する
- AI（OpenAI）を使うAPIは、生徒ごとに毎分30回までのレート制限あり。OpenAIへの通信は60秒（音声の文字起こしは120秒）でタイムアウトし、一時的な失敗は2回まで自動で再試行する（音声のアップロードは再試行しない）
- アプリ・管理画面の通信にもタイムアウトがある（通常20秒／AI採点・教材生成90秒／読み上げ45秒／アップロード60秒。管理画面は30秒／60秒）。超えると「通信がタイムアウトしました」のエラーになる
- 本番では、開発用のモックデータ（生徒25人など）を投入しない。ソースに載っている既定パスワード（開発用）のままの管理者アカウントは、起動時に検出して初回ログイン時の変更を強制する
- 管理画面は役割（運営管理者／コーチ）で権限を分離している（詳細は管理画面仕様書 9.2）。管理者のパスワードは10文字以上
- ログイン・新規登録には試行回数の制限がある（ログイン：同じIP×メールで15分に10回、新規登録：同じIPで15分に20回）
- **運用**：
  - `GET /api/health` はDBに接続できなければ503を返す（ロードバランサ・監視用）
  - ログは1行1JSON（時刻・レベル・メッセージ）。リクエストごとにIDを振り、`X-Request-Id` ヘッダでも返す。クエリ文字列・本文は記録しない
  - SIGTERM/SIGINT で新規接続を止め、処理中のリクエストの完了を待ってからDBを閉じて終了する（最大10秒）
  - TTSのキャッシュは30日超・合計500MB超の分を、アップロードの一時ファイルは1時間超を、起動時と1時間ごとに自動で削除する
  - セキュリティヘッダ（helmet）と、レスポンスの圧縮（gzip）を有効にしている。画像は1日、読み上げ音声は長期キャッシュさせる
  - `CORS_ORIGINS`（管理画面のオリジン。カンマ区切り）、`TRUST_PROXY`（リバースプロキシの段数）を設定する。未設定だと、CORSは全オリジン許可、ログイン試行制限はプロキシのIPで一括して数えられる
  - DBのスキーマ変更は、`db.js` の `MIGRATIONS`（`PRAGMA user_version` で版管理）に追加する。主要な検索条件にはインデックスを張っている
  - GitHub Actions（`.github/workflows/ci.yml`）で、プッシュのたびにサーバーのテスト・脆弱性チェック（high以上）、管理画面とアプリの型チェック・ビルドを実行する
  - 性能の計測は `node server/scripts/bench.js`（生徒3000人・学習記録18万件のダミーデータ）
- **本番前に必要**：通信のHTTPS化（プロキシ配下ではクライアントIPの取得設定も）、メールアドレスの所有確認（現状は、管理画面で先に登録された生徒のメールアドレスを知っていれば、本人以外がサインアップして引き継げる）

## 13. 共通機能

### 13.1 英文の単語長押し辞書

- 英文表示（ダイアログ・プレゼン原稿・Weeklyの教材など）の単語を**長押し**すると、ポップアップで意味を表示する
- まず英和辞書（EJDict-hand。パブリックドメイン。サーバーのローカルDB）を引き、活用形（過去形・複数形・-ing など）は原形に戻して検索する。辞書にあれば意味の一覧を即表示（AIは呼ばない）
- 「この文脈での意味をAIで見る」を押したとき（および辞書に無い単語）は、その単語が使われている文をもとにLLMが文脈に合った意味・品詞・例文を返す。AIの結果は一定数までサーバー内にキャッシュ
- ポップアップから「MYフレーズに登録する」（単語）ができる。読み上げ（TTS）ボタン付き

### 13.2 広告バナー

- 管理画面で登録した画像とリンク先を、表示先（`home` / `talk` / `mypage`）ごとに表示。有効なものが複数あれば約6秒ごとにローテーション、約20秒ごと／前面復帰時に取り直す
- リンク先は http/https のみ（サーバーで検証）
